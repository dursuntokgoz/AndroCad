# Topological Naming Problem (TNP) Regression Test Suite Specification

This specification defines the architecture, test cases, and pass/fail criteria for the **TNP Regression Test Suite**, scheduled for full implementation at the beginning of **Milestone 5**.

---

## 1. Objectives
The TNP suite tests that parametric edits applied to early timeline nodes do not inadvertently disconnect, corrupt, or invert downstream sketches, datum planes, fillets, or chamfers that reference sub-shapes (faces, edges, vertices) of the modified model.

---

## 2. Test Harness Architecture
The suite runs as a native host-side test executable (`tnp_regression_tests`) using GoogleTest/CTest:
1. **Model Construction:** Programmatically constructs a parametric feature DAG containing 3 to 6 sequential operations.
2. **Reference Capture:** Records the initial references (Target Face IDs, Edge IDs) along with their Tier 1 semantic tags, Tier 2 history links, and Tier 3 geometric fingerprints.
3. **Parameter Mutation:** Mutates an early dimension parameter (e.g. increase length by 50%, reduce height by 25%, translate a hole).
4. **Rebuild & Verification:** Re-evaluates the timeline from the mutated node to the end of the DAG.
5. **Assertion:** Checks that:
   - Downstream features report `Status == OK`.
   - The resolved target sub-shapes match the expected geometric orientation and topological role.
   - The total volume, face count, and topological Euler characteristic match theoretical values.

---

## 3. Core Test Scenarios

### Test 1: Upstream Dimension Scaling with Attached Downstream Sketch
* **Initial Setup:** Box (Pad 1: 50x50x20 mm). Sketch 2 drawn on Top Face (`Extrude_1:Cap_End`), centered circle extruded as a cylindrical boss (Pad 2).
* **Mutation:** Change Pad 1 width from 50 mm to 100 mm and height from 20 mm to 35 mm.
* **Expected Outcome:** Top Face shifts from $Z=20$ to $Z=35$ and doubles in area. Sketch 2 re-attaches to the newly translated and resized Top Face via Tier 1 semantic tag `Extrude_1:Cap_End`. Pad 2 rebuilds cleanly atop the resized box.

### Test 2: Edge Fillet Persistence across Upstream Dimension Edit
* **Initial Setup:** Box (40x40x40 mm). Fillet 1 ($R=5\text{ mm}$) applied to the four vertical corner edges (`Extrude_1:SideEdge(line_1..4)`).
* **Mutation:** Change box depth from 40 mm to 80 mm.
* **Expected Outcome:** The four vertical edges remain tagged with their original lateral line identities. Fillet 1 finds all 4 modified edges and reconstructs without error.

### Test 3: Face Splitting via Boolean Cut (Tier 2 History Resolution)
* **Initial Setup:** Rectangular slab (100x40x10 mm). A pocket cut splits the top face into two distinct regions (Left and Right). Sketch 3 was placed on the Right top face.
* **Mutation:** Upstream pocket width is adjusted from 20 mm to 30 mm.
* **Expected Outcome:** `BRepTools_History::Modified(TopFace)` returns the two split faces. The resolver matches Sketch 3 to the Right face using the combination of modification index and geometric center of gravity.

### Test 4: Upstream Feature Insertion (Timeline Rollback)
* **Initial Setup:** Base block -> Hole 1 -> Chamfer on hole rim.
* **Mutation:** Rollback before Hole 1. Insert an external rib feature. Re-roll forward.
* **Expected Outcome:** Hole 1 and Chamfer recompute after the inserted rib. Chamfer maintains attachment to the circular edge generated by Hole 1.

### Test 5: Topology Vanishing & Graceful Degradation (Negative Test)
* **Initial Setup:** Box (50x50x20 mm) with a small cylindrical boss ($R=5\text{ mm}$, $H=10\text{ mm}$) on the top face. Fillet applied to the boss rim.
* **Mutation:** Boss diameter reduced to zero or boss suppressed.
* **Expected Outcome:** Rim edge no longer exists in output topology. The resolver safely flags the Fillet node with `NodeState::BROKEN_REFERENCE`, halts downstream execution cleanly, and reports the missing reference to the user without crashing the kernel.

---

## 4. Acceptance Criteria
* 100% of non-vanishing topological mutation tests pass.
* Zero segmentation faults or unhandled C++ exceptions during recomputation.
* Every failed reference correctly produces an informative diagnostic report identifying the lost entity tag.
