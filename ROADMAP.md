# AndroCAD Engineering Roadmap & Milestone Ledger

This document tracks development milestones, architectural decisions, and open risks for **AndroCAD**. It is updated and committed at every milestone transition.

---

## Architectural Decisions

1. **OCCT Version Selection: Pinned to OCCT 7.8.0**
   * *Comparison (7.8.0 vs 7.9.2):* Both versions are distributed under `LGPL-2.1-only WITH OCCT-exception-1.0` on dev.opencascade.org. OCCT 7.8.0 established the modularized Data Exchange (`TKDESTEP`, `TKDESTL`) while maintaining long-term stability and verified Android NDK r25b/r26 toolchain compatibility. OCCT 7.9.2 introduced transitional changes to internal numerical headers that require additional CMake adjustments on mobile Clang. Therefore, **OCCT 7.8.0** is pinned as the primary target for reproducibility and stability.
2. **Sketch Constraint Solver: PlaneGCS**
   * *Selection:* FreeCAD's PlaneGCS solver (`LGPL-2.1-or-later`) written in C++. It uses Levenberg-Marquardt and Dogleg nonlinear solvers, compiles with the same Android NDK toolchain, and covers all required 2D sketch constraints. SolveSpace (`libslvs`) was strictly rejected due to its copyleft `GPL-3.0-or-later` license.
3. **Rendering Architecture: Native C++ OpenGL ES 3.x First (Vulkan Backend Follow-up)**
   * *Selection:* Native C++ rendering loop interfacing with Android `SurfaceView` / `ANativeWindow`. Mesh buffers (`Poly_Triangulation`) generated by OCCT `BRepMesh` are written directly into native GPU Vertex Buffer Objects (VBOs), completely bypassing the Java/Kotlin Virtual Machine to eliminate garbage collection pauses.
4. **Proprietary Application with Dynamic LGPL Linkage**
   * *Selection:* Application Kotlin/Compose code is proprietary (All Rights Reserved). OCCT and PlaneGCS are built strictly as dynamically linked `.so` libraries. Relinking instructions and build scripts are published. *Flagged: Needs legal review before commercial release.*
5. **Compiler Flags Strategy**
   * *Selection:* Rather than blanket `-Oz` (which degrades numerical performance in heavy math loops), compute-heavy toolkits (`TKBO`, `TKBool`, `TKFillet`, `TKMesh`, `TKGeomAlgo`) are compiled with `-O2 -flto`, while foundational and data exchange toolkits use `-Oz` for size reduction.
6. **Storage Access Framework (SAF) vs. Broad Storage Permissions**
   * *Selection:* AndroCAD strictly adheres to modern Android privacy best practices by rejecting broad file permissions (`READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, and `MANAGE_EXTERNAL_STORAGE`). No storage permissions are requested at application startup. Instead, the application exclusively employs Android's Storage Access Framework (`ActivityResultContracts.OpenDocument` and `ActivityResultContracts.CreateDocument`) on-demand when the user initiates an Import or Export action.
   * *Content URI Bridge:* Native C++ Open CASCADE (OCCT) file I/O routines cannot directly access Android `content://` URIs. On import, the content stream is copied safely into application cache (`context.cacheDir`), passed to the native kernel as a valid POSIX path, and cleaned up after mesh ingestion. On export, the native kernel exports to a temporary cache file, which is streamed directly into the SAF document output stream.
   * *Empty State:* First-time users are greeted with a clear, welcoming empty-state screen offering direct access to the Onboarding Tutorial, Sample CAD Designs gallery, and file import, ensuring immediate engagement without scary permission dialogs.
7. **Interactive Touch Sketching & Fusion 360-Style Parametric Extrude Workflow**
   * *Selection:* To provide an intuitive direct manipulation CAD experience akin to Fusion 360, 2D sketch input is decoupled from raw camera touch manipulation via a specialized Compose overlay (`SketchCanvasOverlay`) positioned above the GLSurfaceView viewport when the Sketch workspace is active.
   * *Direct Manipulation:* 1-finger drag operations draw parametric primitives (Rectangles, Circles, Polylines) with live rubber-band stroke rendering, dynamic dimension tags, and automatic closed-profile detection with translucent cyan shading (`#3300A4E4`).
   * *Parametric Extrude Inspector:* Finishing a sketch automatically transitions the camera smoothly to 3D isometric (`NamedView.HOME`) and displays a floating parameter inspector (`ExtrudeInspectorDialog`). Dragging the depth slider immediately recalculates the B-Rep extrusion in Open CASCADE and pushes the updated mesh to the GLES viewport in real time. Committing creates an associative solid body in the Browser tree and appends an entry to the Parametric Timeline.
8. **Magnetic Vertex Snapping, Topological Point Welding & True Solid Primitives**
   * *Magnetic Snapping:* Touch drawing on mobile screens inherently lacks sub-millimeter precision. A 7.0 mm magnetic vertex snap zone (`findNearbyVertex`) locks drag start and end points to existing line endpoints, rectangle corners, and circle centers, with visual yellow indicator rings.
   * *Topological Point Welding:* Unwelded coincident endpoints in OpenCASCADE cause `BRepBuilderAPI_MakeWire` to fail loop closure. The bridge applies 0.2 mm quantized point deduplication (`pointMap`), ensuring shared vertices reference identical OpenCASCADE point indices.
   * *True Sketch-Driven Extrude & Revolve:* Both Extrude and Revolve now assemble and extrude/revolve the actual user-drawn sketch entities rather than static milestone demo shapes. Fallback sizing dynamically measures the bounding box of the active sketch.
   * *Direct Modeling Workflow:* Added 1-tap `+ Sketch` (`btn_solid_create_sketch`) button in the Solid ribbon, a floating direct Extrude action button upon closed-profile detection, a true parametric Cylinder primitive (`tool_Cylinder`), and a clean-slate "✨ NEW DESIGN" button (`btn_new_design`).

## Open Technical & Architectural Risks

| Risk Area | Description | Mitigation Strategy |
| :--- | :--- | :--- |
| **Topological Naming Problem (TNP)** | Parametric recomputation modifies topological entity indices, breaking downstream sketches/fillets. | 3-tier mitigation: Semantic origin tagging -> `BRepTools_History` tracking -> Invariant geometric fingerprint fallback. Dedicated regression suite written in Milestone 5. |
| **LGPL Relinking on Android** | LGPL 2.1 Section 6 requires allowing users to relink or replace the LGPL library. | Deliver OCCT and PlaneGCS as external `.so` libraries in `lib/<abi>/`. Provide automated Docker / GitHub Actions script allowing users to compile replacement `.so` files and resign the APK. |
| **OCCT Android Build Size** | Full OCCT is >50 MB per ABI, exceeding typical mobile app budgets. | Prune visualization, Draw, and OCAF toolkits (`BUILD_MODULE_Visualization=OFF`). Strip debug symbols, apply LTO and dead-code elimination. |
| **Boolean & Fillet Robustness** | OCCT BOPAlgo and ChFi3d rolling ball algorithms can fail on near-coincident faces or complex corners. | Use `BRepAlgoAPI::SetFuzzyValue(1e-5)` for booleans. Wrap all operations with `IsDone()` validation and graceful C++ `Standard_Failure` exception boundaries. |
